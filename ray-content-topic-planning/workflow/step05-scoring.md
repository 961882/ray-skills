# Step 05: 多角色评分

> 执行者：主 Agent
> 输入：5 个拆解 + 历史文案（可选）
> 输出：评分表 + 综合排名

## 执行说明

用 5 个角色独立评分，加权得出综合推荐度。如果有历史文案，先分析内容 DNA 再校准评分。

## 执行分支

```
has_history == true?
    ├── YES → 5.1 历史分析 → 5.2 校准评分 → 5.3 排名
    └── NO  → 5.2 通用评分 → 5.3 排名
```

---

## 5.1 历史文案分析（仅 has_history == true）

读取 `history_dir` 下所有 .md 文件，对每篇分析：

| 维度 | 提取内容 |
|------|---------|
| 标签 | 阅读最高/转发最高/转化最高/效果最差/… |
| 叙事视角 | 第一人称/第二人称/第三人称 |
| 结构类型 | 时间线/清单/层级论证/… |
| AI 检测 | 人工特征百分比（如文末有标注） |
| 阅读数据 | 阅读量/转发/点赞（如文末有标注） |
| CTA 风格 | 轻/中/重 |

从分析中提炼：

1. **5 条规律**：什么写法有效、什么写法失败
2. **内容 DNA 画像**：甜区 vs 死亡区
3. **AI 痕迹控制线**：人工特征的及格线

输出为独立文件：`{output_dir}/YYMMDD-历史文案分析与重新评分.md`

---

## 5.2 评分

对每个精选选题，5 个角色独立打分（1-10）：

参见 `reference/definitions/scoring-roles.md` 获取角色定义和权重。

### 评分表格式

```markdown
| 角色 | 评分 | 一句话理由 |
|------|------|-----------|
| 📈 内容策略师 | **N** | 理由 |
| 🔧 技术顾问 | **N** | 理由 |
| 💰 商业转化专家 | **N** | 理由 |
| 👤 目标受众代表 | **N** | 理由 |
| 🤖 平台运营 | **N** | 理由 |
```

### 校准规则（has_history == true）

- 每个评分必须对照历史数据给出校准理由
- 标注 🔺 上调 / 🔻 下调 / ➡️ 不变
- 如果选题和效果最差的文章同构，必须大幅下调并标注 🔴 高风险
- 如果选题和效果最好的文章同构，可以上调

### 通用评分提示（has_history == false）

- 在评分表下方标注"⚠️ 通用评估，补充历史文案可提升评分精度"

---

## 5.3 综合排名

1. 加权计算综合分
2. 按分数排序
3. 输出排名表：

```markdown
| 排名 | 选题 | 综合分 | 最大优势 | 最大短板 | 建议 | 风险 |
```

4. 输出 Mermaid 排名流程图

## 验证检查点

- [ ] 每个选题有 5 个角色的评分和理由
- [ ] 综合分计算正确（加权平均）
- [ ] 排名表按分数降序
- [ ] 如有历史文案，校准标注完整
- [ ] 如无历史文案，有通用评估提示
