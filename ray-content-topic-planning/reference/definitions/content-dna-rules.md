# 内容 DNA 规则

## 写法甜区（优先使用）

| 维度 | 甜区 | 示例 |
|------|------|------|
| 叙事视角 | 第一人称实操叙事 | "我做了 3 次架构重构" |
| 可信度信号 | 具体数字 + 时间线 | "72 小时""凌晨两点""700 多行代码" |
| 结构 | 扁平（一二三四五） | 时间线 → 逐个讲 → 结果 → 建议 |
| 内容类型 | 踩坑 + 解法 / 工具清单 | "我踩了这 5 个坑""我最常用的 10 个 Skill" |
| 证据 | 自己实测的数据 | "这台机器上实测""跑了半小时" |

## 写法死亡区（必须规避）

| 维度 | 死亡区 | 反面示例 |
|------|--------|---------|
| 叙事视角 | 第三人称新闻解读 | "对 CEO 的警示" |
| 结构 | 层级式论证/"拷问"体 | "第一重拷问""第二重拷问" |
| 内容类型 | 安全新闻转述 / 纯观点 | 无自己实测的分析文 |
| 称呼 | "您" / "我们" | 用"您"显得距离感重 |
| 大词 | "深度解析""全面解读""赋能" | AI 味标志性用语 |

## AI 痕迹控制

### 红线：人工特征 > 40% 才发布

控制策略：
1. 多用"我"少用"我们"，多用"踩了"少用"面临"
2. 加入具体时间点（"周三下午两点""跑了半小时"）
3. 加入只有亲历者才知道的细节（"Jina 带 UA 会 403"）
4. 避免四字成语排比（"系统性的、持续的、隐蔽的"）
5. 口语化连接词（"说实话""这事怎么解""然后我就…"）

## CTA 规则

### ✅ 推荐的 CTA 风格

```
觉得有启发？点个「在看」或转发给同样在做 AI 自动化的朋友。
```

- 轻引导，不施压
- 可以加"评论区聊聊"提升互动率
- 可以加"小红书同步图文版"做跨平台引流
- 个人 IP 强化放在总结句里（"我是 Ray，…"）

### ❌ 禁止的 CTA 风格

- "私信领资料"
- "加群立即获取"
- "限时免费咨询"
- 任何有卖课感的话术

### 为什么这样设计

历史数据证明：Ray 的读者不吃硬转化。转化最高的文章用的是最轻的 CTA（"点个在看"），读者是"看完觉得牛逼 → 主动来找你"的路径。
